# 项目阶段成果自动交付

本通道只处理已配置的原项目及原群，不派任务、不修改项目目标。项目主责判断某阶段已有可展示成果后，准备不可变素材，再在原聊天公开助手消息中声明交付；不必等整轮结束。

在项目内建立 `outputs/feishu-deliveries/<阶段版本>/manifest.json`，阶段版本使用小写英文、数字、下划线或短横线，最多80字符。图片置于这个目录内；保持原始截图字节，检查格式和实际内容，不放凭据、真实未授权材料或无关窗口。

清单字段：
- `schemaVersion: 1`、`id`（等于目录名）、`title`、`summary`
- `working`：本轮真正做到的事；`limits`：未接通、未验和演示边界；两者均为非空字符串数组
- `nextStep`：项目Agent自己的下一步简述，不由交付器改写
- `materialScope: synthetic-public`、`privacyReviewed: true`：本批仅处理源Agent已复核的合成/公开材料，接收范围仍是已授权的本人飞书群
- `images`：1—4张真实PNG/JPEG，分别有目录内相对`path`、实际文件`sha256`、`caption`
- `links`：可空；已有可访问成果链接及`title`，地址只允许配置中已批准的HTTPS来源，不能含凭据、查询参数或指向本机服务

计算清单文件本身的SHA-256，在一条已写完的commentary或final消息首行写HTML注释：`<!-- PROJECT_DELIVERY: 阶段版本 清单SHA256 -->`，下一行正常说明阶段成果。系统也兼容无注释包裹的旧标记；标记不转发飞书。不要在示例/计划中对真实清单发交付声明。

收到声明后，程序核对原对话身份、清单与图片摘要，保存私有不可变快照，检查链接可用性，再以本人已配置的机器人发送富文本、图片、成果说明和@，最后官方读回。接收者不由清单决定。

已入队的交付在重启后继续，图片上传和实际消息ID分别持久化；读回失败不重新发送已知消息。发送去重依赖相同UUID，平台文档规定一小时窗口，本通道把结果不明的重试限制在30分钟内，超过后保留待核记录，不盲目重发。[飞书官方SDK说明](https://larksuite.github.io/oapi-sdk-java/com/lark/oapi/service/im/v1/model/CreateMessageReqBody.Builder.html#uuid-java.lang.String-)

同一个阶段版本不能改内容。实质新成果使用新版本；普通状态更新不重复发图或@。素材错误或链接不可用只影响交付，不能重跑业务。暂停/停止服务、绑定或群配置变化时，交付动作重新核对。

发送后的真实消息ID会保留项目对应关系。本人引用这条图文继续说话时，从已读回记录恢复对应项目和历史摘要，不借用群里最近聊过的其他项目；绑定变更或未读回记录不能提供这种指代。该关联只是上下文线索，不授予执行权限。

当前实现边界：自动上传真实截图、发送已验证的已有链接和读回；尚不自动创建公网预览部署、录屏转码或上传任意文档。首次试点仅公司项目。系统读取近期原生消息，长期离线后未发现的旧声明仍需单独核查，不能声称历史全量补发。
